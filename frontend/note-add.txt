AmpWise — Frontend API Integration Status
==========================================

Contract baseline
-----------------

- Repository contract: `docs/api_contract.md`, version v0.5.
- Active dataset metadata read from `backend/data/meta.json`: California ACN,
  USD, America/Los_Angeles station-local timestamps.
- No Malaysian data is used by the active frontend API path.
- Backend configuration is now `MOCK=0` in the local environment, using the
  California parquet dataset. The sandbox does not permit binding a listening
  socket, so endpoint verification was performed with FastAPI TestClient.

Completed frontend integration
-------------------------------

- Shared typed fetch client supports GET, POST, PATCH, AbortSignal and backend
  error parsing.
- API mode never silently falls back to local JSON after a failed request.
- Mock mode and API mode use the same frontend response shapes.
- `site_issue` is supported in issue types, configuration, badges, filters,
  action rows, details and alert icon mappings.
- `report_count` and `first_reported_at` are rendered without treating driver
  reports as confirmed sensor faults.
- Overview feedback data now uses `/api/reports/categories` in API mode.
- Unsupported frontend `POST /api/stations` was removed.
- Currency formatting reads `meta.currency` and supports validated decimals.
- React Query keys include the relevant simulated time or endpoint parameter.

Simulated-time synchronization fix
-----------------------------------

- Root cause: `TimeContext` initialized with a hardcoded California timestamp
  before `/api/meta` completed. Time-dependent queries were enabled immediately,
  so the initial 2019 request could be rejected before metadata-selected time
  was applied.
- A second source was the backend's explicit legacy `MOCK=1` fallback, whose
  metadata is 2026 Malaysia/RM. The checked-in real dataset metadata is
  California/US and should be used for the V2 demo.
- Frontend fix: time-dependent queries now remain disabled until valid backend
  metadata selects a supported demo time or range start. Unsupported California
  metadata produces a visible configuration error instead of silently sending
  legacy timestamps.
- Frontend fix: React Query no longer retries HTTP 400 validation errors.
- Backend configuration fix: the default and `.env.example` now use
  `MOCK=0`; legacy mock responses remain available only when `MOCK=1` is
  explicitly selected.
- Live request counts and response bodies remain unverified until the local
  FastAPI runtime is installed and running.

Overview cross-check
--------------------

- Overview station availability now derives from `/api/stations?time=`:
  station count, stations with at least one working charger, total chargers and
  working chargers are kept distinct.
- Overview no longer treats `n_working` as an online-station count and does not
  render zero when the station request is loading or failed.
- The Network Status card uses unresolved charger actions from
  `/api/actions?time=&limit=` and shows a checking/unavailable state while the
  source query is pending or failed.
- Energy, live sessions, historical uptime, weekly energy and station-session
  performance remain unavailable in API mode because no supporting backend
  endpoints or response fields exist. No fabricated chart values are used.
